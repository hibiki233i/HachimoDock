# Firmware repair baseline

This folder remains based on PC-bundled 0.7.103, not the experimental 0.7.108 branch.

Public revision `0.7.103-p4-r2` accompanies desktop `0.1.168` as a maintenance
release. Experimental framework work is not part of this build.

The factory and OTA bootstrap catalogs contain 28 built-in components, with
`cloud-hop` as the factory default. Launcher thumbnails are regenerated from the
same catalog. Generic media parsing, rendering and playback remain available;
their regressions use isolated synthetic fixtures, not a bundled live service.

`main/pet_p4_miniapp.c` owns transactional component storage and per-component recovery from verified committed catalogs. Navigation persists only the last-opened ID, leaving the previous catalog available for recovery. Unparseable existing catalogs block destructive bootstrap reseeding. Known image-free bootstrap packages are distinguished from complete resources.

`main/pet_p4_protocol.c` exposes resource integrity and bounded resource-repair installation. Repairs retain component records and existing button configuration, and refuse writes during audio activity. `tools/build_builtin_bundle.py` emits bootstrap identity checks without inflating the bundle. `tests/component_resource_recovery_test.py` executes production recovery logic with sanitizers; fault injection belongs in offline tests, never on user storage.

P4 appearance manifests and renderer share a 2 MiB per-stream limit; factory slot 0 remains protected. `tests/p4_asset_stream_limit_test.py` is a host test that compiles `main/pet_p4_assets.c` with the system `cc`, so it runs in the `firmware-host` CI job.

Wi-Fi (`pet_p4_network.c/.h`, `pet_p4_net_core.c/.h`): the ESP32-C6 radio is reached through ESP-Hosted over SDIO and carries status, sessions and key events as an authenticated TCP JSONL link beside USB (see `protocol.md`). It starts lazily from stored credentials; `main/CMakeLists.txt` wraps `esp_hosted_init` so a USB-only board never touches the C6, and builds the radio stack with `-Os`. `pet_p4_net_core.c` is the heap-free policy tested by `tests/p4_net_core_test.py` (the topic allowlist must match `pc/src-tauri/src/network_transport.rs`); `tests/p4_network_fallback_test.py` compiles the real status/API functions to keep USB hello and `network/*` safe when the network task never started. The default `done`/`error` status sounds are no longer embedded (about 240 KB reclaimed for the radio stack); appearance-supplied audio still plays.

Raw appearance storage (`pet_p4_raw_assets.c/.h`) addresses up to four slots (`appearance0`..`appearance3`); a slot with no partition is unavailable and the shipped table still defines two. `asset/begin` takes an optional `slot` (default: the legacy custom slot `1`), slot `0` stays protected while `PET_P4_BUILTIN_SLOT_PROTECTED` is set, and capabilities report the slots that exist plus `slotCapacityBytes`. `tests/p4_raw_slots_test.py` compiles the real storage code against RAM-backed partitions to check per-slot isolation.

Factory default pets: `tools/build_factory_image.py` stages each pet listed under `appearances` (empty in the repository; a git-ignored `factory-config.local.json` supplies them) in its own slot, SPIFFS slot files plus a per-slot raw image, and the first listed pet is active at first boot. The layout is three 5 MiB slots (`appearance0`..`appearance2`) with the last 5 MiB of flash unassigned. With no pet installed the renderer draws an import hint (`draw_import_hint`). Native USB `file-begin` and serial `asset/begin` both accept a target `slot`, validated by `pet_p4_asset_slot_is_transfer_target`.

Joystick Agent switch: input config version 10 binds joystick left/right to `agent_previous` / `agent_next`. `pet_p4_agent_key_route` (in `pet_p4_input_core.c`, covered by `tests/p4_input_logic_test.c`) decides per page what they do: with the desktop connected and `agent/focus` announcing two or more followed Agents they are reported to the desktop (`handledLocally:false`), otherwise they keep their old Session meaning, and in the component center they select components. `agent/focus` also drives the short on-screen Agent label (`draw_agent_hint`).

The active appearance marker accepts every valid slot (0–2), so selecting slot 2 survives reboot. `tests/p4_active_slot_test.py` compiles and runs the actual protocol marker functions against a temporary file, including invalid marker cases.
