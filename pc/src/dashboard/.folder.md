# 2026-10-24 语音定位失败现场

composer-failure-evidence.js 仅解析原生返回的有界结构快照，VoiceAssistantPanel 将技术快照从常规错误提示中折叠出来，供用户复制。不重扫目标 UI，不自动发送、不持久化。VoiceComposerCheck 继续提供显式只读检查。

WifiLinkCard shows the live link (USB or WiFi), provisions WiFi over the USB cable (password held only in component state), discovers paired boards on the LAN and connects by saved or manual address. Business rules (credential limits, error text, link labels) live in `lib/wifi-link.js`.

Multi-Agent follow: `useFollowedAgentFeeds` polls the Agents ticked for simultaneous follow (one feed per fixed Agent, in a stable order, idle when not wanted) beside the primary feed in DeviceDashboard.jsx; `useAgentFocus` turns the queues into the focus Agent (earliest active, manual pin via `step`/`release`); only the focus Agent's queue is pushed to the board, so older firmware works too. `usePetFollowSwitch` activates the focus Agent's resident appearance when `petFollowMode` is `follow` and warns once if it is not stored on the board. `AgentFocusContext` hands the focus to ChannelMatrixCard, which shows the focus panel, the per-Agent "同时跟随" toggle (it stores the pet on the board over USB first) and the "桌宠常驻" setting. `agentFocusWiring.test.js` keeps these pieces and the `usb_activate_resident_appearance` command connected.

Joystick Agent switch: `useAgentSwitchEvents` turns the board's `agent_next` / `agent_previous` reports (pet home page only) into `agentFocus.step`; `useAgentFocusAnnouncer` sends `agent/focus` whenever the focus or the follow set changes (asking for the on-screen label only on a real switch) and every 15 seconds so a rebooted board relearns it.

Focus activation and preloading share `createPetFollowController`: the matrix uses the dashboard's preload operation rather than restoring the primary channel's appearance directly. Completed activation requests always update the known device appearance before the latest focus is reconciled. Resident switching remains enabled for a connected P4 with only the primary Agent left.

`usePetFollowSwitch` invalidates display knowledge on controller initialization, reconnection and desktop assignment changes. It confirms focus by resident activation instead of seeding device state from the main channel. `ChannelMatrixCard` treats a full preloading result as an ignored addition and preserves the existing followed Agents.

`ChannelMatrixCard` also preloads replacement pets for Agents already in simultaneous follow before saving their new appearance assignments. Failed transfers, full slots and a missing USB link preserve the old assignment; preloading keeps the latest focus and resident-mode display. Appearance and follow controls stay busy during preload, and the picker describes the device sync for every followed Agent. `ChannelMatrixCard.follow.test.js` exercises the actual change handler with the focus planner and resident controller.
