# Desktop frontend

React UI for devices, Agent bindings, API configuration, components and animated appearances. Shared avatar generation modules live in lib/avatar-pipeline. Tests run with npm test. API credentials come from user settings through the native configuration boundary; public frontend bundles do not embed credentials. The normal public generation, receipt, photo import, component caching and playback behavior is the 0.1.167 release baseline.

Component media errors describe required capabilities, not a particular package.
The component center and sidebar share catalog visibility rules while preserving
user files and settings across upgrades.

Appearance detail merges built-in video and audio overrides, provides restoration and device quality settings, and separates local preparation from board transfer. Built-in video/audio edits and restoration whose preparation fails restore the previous sources and settings, and unreadable or malformed override files leave the appearance loadable so factory restore stays reachable. `lib/appearance-store.rollback.test.js` runs these flows against the in-memory Tauri stand-ins in `lib/tauri-fakes.js`, which a module-resolution hook (`lib/tauri-fakes-hooks.mjs`) substitutes for `@tauri-apps/*`.

Successful media edits refresh prepared-pack usage and allocated rates while preserving draft quality inputs; factory inspection follows the same source selection as device sync.

lib/wifi-link.js: pure WiFi/USB link helpers (credential validation, link labels, status and error text) mirrored from the firmware rules and covered by lib/wifi-link.test.js.

lib/agent-focus.js: pure multi-Agent focus engine (earliest-active automatic focus where a finished Session still counts as active during its 60-second terminal hold, joystick pin and release rules, and the `follow`/`resident` pet mode), covered by lib/agent-focus.test.js. `lib/agent-appearance-config.js` stores the device follow set and pet follow mode apart from the single desktop-pet channel; the legacy single selection only seeds the first run.

lib/resident-appearance.js wraps the `usb_activate_resident_appearance` command (`activateResidentAppearance`, `residentActivationMessage`), covered by lib/resident-appearance.test.js; `planPetSwitch` in lib/agent-focus.js decides from a focus change whether the pet on the board should switch.

dashboard/useFollowedAgentFeeds.js, useAgentFocus.js, usePetFollowSwitch.js and AgentFocusContext.js implement the multi-Agent follow wiring described in dashboard/.folder.md.

lib/agent-switch.js (`agentSwitchDirection`, `buildAgentFocusAnnouncement`, covered by lib/agent-switch.test.js) and dashboard/useAgentSwitchEvents.js / useAgentFocusAnnouncer.js connect the board's joystick Agent keys to the focus engine.

Multi-Agent follow reconciliation: `DeviceContext` synchronizes the union of the primary and extra followed Agents into Bridge monitor configuration while retaining one `selectedAgentId`. `createPetFollowController` in `lib/resident-appearance.js` serializes focus activation and USB preloading; `usePetFollowSwitch` exposes its preload operation through `AgentFocusContext` and keeps restoring the latest focus when the follow set shrinks to one Agent. Behavior tests cover pending switches, focus changes during preload, resident mode, and monitor startup failures.

Connection and desktop-assignment changes invalidate the pet controller's display cache; the primary channel configuration never confirms device state. The focus appearance is activated once after startup/reconnect. Preloading restores the device's actual slot in Rust, so resident mode also works with an empty frontend cache, while full slots leave the follow set unchanged.
