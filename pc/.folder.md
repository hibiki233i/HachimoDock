# Desktop source (0.1.168)

- src: React UI, generation pipeline and regression tests.
- src-tauri: native device, audio, desktop integration and local configuration.
- src-tauri/bridge: local Agent session event bus and receipt handling.
- builtin-clawpkgs / new-components: public widget packages and source assets.
- scripts: resource preparation, tests and public distribution checks.

`src-tauri/src/network_transport.rs` owns the Wi-Fi link: HMAC challenge/response, UDP discovery, and the paired-board registry (secrets in the OS credential store or a private 0600 file, endpoints in `network-devices.json`). It is a second connection source for `UsbSerialManager::connect_network`; the manager keeps one connection slot, USB wins, and assets, audio, widgets and firmware refuse a Wi-Fi link with an actionable message.

The bundled catalog follows the firmware factory list (28 components). Media
contract tests use independent offline fixtures under tests/fixtures. Official
community staging uses the same current catalog.

Public source uses user-provided credentials and per-computer networking settings. service_credentials.rs only rejects a legacy non-secret placeholder; it does not supply service defaults. Configure your own service keys in API settings. User configuration and caches are runtime data, never build inputs. See the repository README for build and release instructions.

Device appearance preparation reserves manifest and normalized audio bytes before allocating rates across unique video streams. Per-action rates are upper bounds; allocation tests cover shared sources, scaling, duration caps and exhausted budgets.

Appearance quality preferences live in `p4-settings.json` beside the source manifest so disposable pack failures do not reset them. Legacy cache settings migrate on the next successful preparation.

The local appearance inspection command distinguishes `packReady` from retained quality preferences; missing packs leave settings editable and show no stale size or bitrate results.

Appearance slot sync (`src-tauri/src/usb_serial/appearance_transaction.rs`, `usb_serial.rs`): the desktop reads `appearance.slotCapacityBytes`, picks the target slot with `choose_p4_target_slot` (the appearance's own previous slot, else the lowest empty one, else the stalest slot that is not on screen), names it in `asset/begin`, and keeps another pack on screen while the target is rewritten. `p4-slot-assignments.json` in the app data directory remembers which appearance last went into which slot of which board. `usb_activate_resident_appearance` switches to an appearance already in a slot without transferring anything, so it also works over Wi-Fi; a pack that is not resident is reported, never sent. Firmware that reports no `slotCapacityBytes` keeps the single custom slot.

Joystick Agent switch (desktop side): `usb_send_agent_focus` sends `agent/focus` to the board (also over Wi-Fi); the frontend steps the focus when the board reports `agent_next` / `agent_previous` (`src/lib/agent-switch.js`, `src/dashboard/useAgentSwitchEvents.js`, `useAgentFocusAnnouncer.js`). The button-config model version is 10 and joystick left/right default to the Agent actions; the previous defaults stay in `DeviceDashboard.jsx` so stored configs still migrate.
